Пример 21. Основные типы данных и статистические функции R

# вектор
scores <- c(78, 92, 85, 60, 92, 71)

# статистические функции
mean(scores)     # среднее: 79.67
median(scores)   # медиана: 81.5
var(scores)      # дисперсия
sd(scores)       # стандартное отклонение
IQR(scores)      # межквартильный размах

# матрица 2 x 3
m <- matrix(1:6, nrow = 2)

# список с элементами разных типов
student <- list(name = "Асель", age = 20, scores = scores)

# таблица данных (data frame)
df <- data.frame(name = c("Асель", "Ерлан"), score = c(92, 78))
summary(df)

# операторы
7 %% 3    # остаток от деления: 1
7 %/% 3   # целочисленное деление: 2
2 ^ 10    # возведение в степень: 1024

Вектор хранит значения одного типа, список — значения разных типов, а таблица данных (data frame) — столбцы-векторы одинаковой длины.

Пример 22. Многокомпонентная загрузка и дедупликация в S3

Задача 1. Нужно загрузить в Amazon S3 видеофайл 12 ГБ и резервную копию 300 МБ.

  • 12 ГБ больше 5 ГБ — один запрос не подходит, многокомпонентная загрузка обязательна. Например, 120 частей по 100 МБ: инициирование → загрузка частей (можно параллельно) → завершение, после чего S3 соберёт объект.
  • 300 МБ можно загрузить одним запросом, но так как файл больше 100 МБ, рекомендуется многокомпонентная загрузка: при обрыве сети повторно загружается только одна часть.

Задача 2. Резервная копия разбита на 6 блоков с хешами: A1, B7, A1, C3, B7, A1. Сколько блоков реально нужно хранить после дедупликации?

  • Уникальные хеши: A1, B7, C3 — 3 блока; остальные 3 заменяются ссылками.
  • Экономия места: 3 из 6 блоков, то есть 50%.

Резервные копии хорошо поддаются дедупликации; видео и сжатые данные — плохо, так как повторяющихся блоков в них почти нет.
