Пример 11. Сравнение MapReduce 1.0 и 2.0

КритерийMapReduce 1.0MapReduce 2.0 (YARN)
Управление ресурсамиОдин Job TrackerResource Manager + Application Master для каждого приложения
Единица ресурсовСлоты Task TrackerКонтейнеры (Container), за которыми следит Node Manager
Сбой управляющего компонентаПерезапуск Job Tracker с чтением журналов, простой кластераАвтоматический перезапуск с последнего сохранённого состояния
МасштабДо ~4000 узловТеоретически до ~10000 узлов
Типы приложенийТолько map/reduceMap/reduce, Spark, Open MPI, Giraph, HAMA и др.

Вывод. Главная идея версии 2.0 — разделить управление ресурсами кластера и управление конкретным приложением. Это сняло нагрузку с единственного Job Tracker и позволило запускать на кластере не только MapReduce.

Пример 12. Запрос HiveQL вместо программы MapReduce

Задача. В Hadoop хранится таблица продаж sales(date, city, amount). Нужно найти суммарные продажи по городам.

Вместо написания функций Map и Reduce на Java аналитик пишет SQL-подобный запрос в Hive:

SELECT city, SUM(amount) AS total
FROM sales
GROUP BY city
ORDER BY total DESC;

Hive сам преобразует запрос в задания MapReduce (или Spark): Map выдаёт пары (city, amount), Reduce суммирует значения по каждому городу.

Вывод. Компоненты экосистемы (Hive, Pig, Spark SQL) позволяют работать с большими данными без низкоуровневого программирования.
