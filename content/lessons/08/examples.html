Пример 15. Документ MongoDB вместо трёх таблиц

Ситуация. В реляционной базе информация о студенте хранится в трёх таблицах: students, phones, grades. Чтобы показать карточку студента, нужны две операции JOIN.

В MongoDB вся информация об объекте хранится в одном документе коллекции students:

{
  "_id": 1024,
  "name": "Айгерим Серикова",
  "group": "ИС-21",
  "phones": ["+7 701 000 00 00", "+7 727 000 00 00"],
  "grades": [
    {"course": "Анализ больших данных", "score": 92},
    {"course": "Базы данных", "score": 85}
  ]
}

Основные операции (в оболочке MongoDB):

db.students.insertOne({ _id: 1025, name: "Даурен", group: "ИС-21" })
db.students.find({ group: "ИС-21" })
db.students.updateOne({ _id: 1025 }, { $set: { group: "ИС-22" } })
db.students.deleteOne({ _id: 1025 })

Что видно из примера: нет жёсткой схемы (у второго студента нет поля phones), нет JOIN, поле _id обязательно; документ хранится в формате BSON — двоичном аналоге JSON.
