Достоинства модели Map Reduce

  • Автоматическое распараллеливание: функции Map и Reduce могут выполняться параллельно и независимо друг от друга

  • Масштабируемость: данные могут располагаться и обрабатываться на разных серверах

  • Отказоустойчивость: при отказе сервера функции Map и Reduce запускаются на другом сервере.


Недостатки модели Map Reduce

  • Фиксированный алгоритм обработки данных

  • Высокие накладные расходы на распараллеливание


Архитектура Hadoop

На каждом компьютере должны присутствовать два компонента (рисунок 3.4):

  • Task Tracker: выполняет маленькую вычислительную задачу на узле

  • Data Node: управляют данными, переданными на узел.

Все маленькие компьютеры называют Slave. Также существует Master узел. Данный узел кроме Task Tracker и Data Node содержит ещё Job Tracker и Name Node. Task Tracker и Job Tracker являютсякомпонентами Mad Reduce, а Name Node и Data Node – HDFS. Роль и цель Job Tracker, которые исполняется на Master Node - это разбить большие задачи на маленькие кусочки и отправить каждую маленькую часть вычислений соответствующему Task Tracker на узле, которые в свою очередь, когда смогут закончить вычисления, отправят обратно информацию в Job Tracker, который объединит все результаты вычислений и отправит их обратно приложению.

Пример 9. Подсчёт слов с помощью MapReduce

Задача. Посчитать, сколько раз каждое слово встречается в двух строках: «big data big» и «data analysis».

Этап Map. Главный узел передаёт каждую строку отдельному рабочему узлу. Каждый узел для каждого слова порождает пару (слово, 1):

  • Узел 1: (big, 1), (data, 1), (big, 1)
  • Узел 2: (data, 1), (analysis, 1)

Группировка по ключу (shuffle). Пары с одинаковым ключом собираются вместе: big → [1, 1]; data → [1, 1]; analysis → [1].

Этап Reduce. Для каждого ключа значения суммируются: (big, 2), (data, 2), (analysis, 1).

Что важно. Программист написал только две функции: «разбить строку на слова и выдать (слово, 1)» и «сложить список чисел». Распределение по узлам, передача данных и повтор при сбое выполняются Hadoop автоматически.

Пример 10. Размещение файла в HDFS

Задача. В HDFS загружается файл размером 1 ГБ (1024 МБ). Размер блока — 64 МБ (значение по умолчанию в Hadoop 1.x; в Hadoop 2.x и новее — 128 МБ), коэффициент репликации — 3. Сколько блоков будет создано и сколько места займёт файл?

  1. Число блоков: 1024 / 64 = 16 блоков.
  2. Каждый блок хранится в 3 копиях на разных машинах: 16 × 3 = 48 копий блоков.
  3. Занимаемое место в кластере: 1 ГБ × 3 = 3 ГБ.

Что происходит при отказе узла. Name Node знает, на каких Data Node лежат копии каждого блока. Если один Data Node вышел из строя, клиент прочитает блок с другой машины, а система создаст новую копию, чтобы снова было 3.
